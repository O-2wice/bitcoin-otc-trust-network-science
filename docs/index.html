The Bitcoin OTC Trust Network

Between 2010 and 2016, traders on Bitcoin OTC left 35,592 ratings about each other. This is the web of trust they built, and how reputation came to rest on a few accounts.

The measures

A sparse small world

We turned the ratings into a network: users are nodes, and a positive rating from one user to another is a directed link. Most models in the course are for undirected networks, so we also join two users with one link when either rated the other, which gives 18,591 links among 5,881 users. These are its basic measures.

Paths are shorter than in a random network of the same size, while clustering is about 150 times higher: together that is a small world. All five largest communities are weak communities in Barabási's sense, with more of their members' link ends inside the group than outside, although which users land in which group changes when the algorithm is rerun.

The models

What theory gets right, and wrong

We set the network beside three references: an Erdős–Rényi random network with the same users and links, a Barabási–Albert network grown by preferential attachment, and a degree-preserving randomization that keeps every user's degree but shuffles who is linked to whom.

Keeping the degrees reproduces the short paths but not the clustering or the communities. Those come from how users actually chose their partners.

Heavy-tailed, but not strictly scale-free

A scale-free network has a degree distribution \(P(k) \propto k^{-\gamma}\). Fitted properly, by maximum likelihood rather than a straight line on a log–log plot, the tail gives \(\gamma = 2.09\): heavier than the \(\gamma = 3\) of the BA model. Yet a lognormal tail fits better, and above about 100 links the data bend down.

BA's growth rule also fails, because 70.5% of links join two users who were already present. Barabási's internal-link model allows exactly that, and for the measured \(m = 0.99\) new and \(n = 2.35\) internal links per new user it predicts a value inside the fitted range:

\(\gamma = 2 + \dfrac{m}{m + 2n} = 2.17\)

Hubs and the structural cutoff

The negative assortativity is partly forced. In a simple network a hub cannot find enough other hubs to link to, and above the structural cutoff \(k_s = \sqrt{\langle k\rangle N} \approx 193\) that alone pushes \(r\) below zero. Randomizations that keep every degree already give \(r = -0.114\). The real network goes a little further: users with a single link are attached to neighbours with 181 links on average, against 93 after randomizing.

The focused question

How reputation concentrated

Counting all ratings received so far, the top 1% of users held 15.5% of positive ratings at the end of 2011 and 23.5% by 2015, and the rise also holds within the users present in 2011. The share of each year's new ratings seems to fall after 2013, but ratings collapsed from 11,138 to 929 a year. Redrawn to the same 743 ratings every year, 2013 and 2015 overlap: most of that fall is a volume effect.

Who receives the next rating?

This is how the course measures preferential attachment: for every new rating, compare the user who received it with everyone who could have. Users with 32 or more earlier ratings were chosen 12.7 times as often as chance, and the fitted rule \(\Pi(k) \propto k^{\alpha}\) has \(\alpha = 1.07\), almost exactly BA's linear attachment.

That compares a dormant newcomer with an active trader. Against users with the same tenure and recent activity the ratio falls to 1.65, and \(\alpha\) to a sublinear 0.68. Recent activity, not reputation, explains most of the advantage, and about half of all ratings simply return an earlier one, usually within minutes.

Robustness

Robust to failures, fragile to attacks

Percolation theory predicts when a network falls apart. A giant component exists while \(\kappa = \langle k^2\rangle / \langle k\rangle > 2\), the Molloy–Reed criterion, and removing a random fraction \(f\) of the users destroys it at the critical threshold

\(f_c = 1 - \dfrac{1}{\kappa - 1} = 0.986 \quad \text{for} \quad \kappa = 71.9\)

Random removal barely matters: the giant component survives until about 93% of users are gone. Removing the most-connected users first breaks it after 15%. Randomized networks with the same degrees break at the same point, so the hubs are the weak spot.

What it means

Lessons for a web of trust

Reputation stays concentrated. By 2015, 56 accounts held 23.5% of positive ratings. Ratings never expire here, so a high score can describe the past more than the present.

A few accounts hold it together. Losing or compromising a handful of hubs would disconnect far more of the trust record than the same number of random departures.

Counts overstate independent opinions. About half of the ratings return an earlier one, often within minutes, so a rating count is not a count of independent endorsements.

Activity beats reputation. Recent activity explains most of the pull of highly rated users. We cannot separate it from trading volume, which the data do not record.

Limits: ratings are opinions, not verified trades; the data have no registration dates or trade volumes; one person may hold several IDs.

Reproduce

Every number can be rebuilt

The repository has the analysis scripts, notebooks that work through each method by hand, the stored results, and a checker that compares a new run with the recorded one. With Python 3.12:

# set up the environment
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
# put soc-sign-bitcoinotc.csv.gz from SNAP in data/, then
.venv/bin/python scripts/reproduce.py
.venv/bin/python scripts/verify_reproduction.py --check-manifest

See also the report, the code walkthrough and the Cytoscape workflow.
