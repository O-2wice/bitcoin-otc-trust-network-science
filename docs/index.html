The Bitcoin OTC Trust Network

Between 2010 and 2016, traders on Bitcoin OTC left 35,592 ratings about each other. We read those ratings as a network to see how trust was organised, which theories explain its shape, and how reputation became concentrated on a few accounts.

Read the report Code on GitHub

01 · The question

How does reputation concentrate in a web of trust?

On an anonymous marketplace, ratings are the main signal of who is safe to trade with. If they pile up on a few accounts, newcomers struggle to build trust and the system leans on those accounts. We ask how positive ratings became concentrated, and how much of the advantage of already highly rated users survives a fair comparison.

02 · From ratings to a network

Each rating is a directed link

A user is a node. A rating is a link pointing from the rater to the rated user, carrying a score from −10 to +10 and a time. We keep the 32,029 positive ratings. Many models in the course are for undirected networks, so we also merge each mutual pair into one link: 18,591 links among 5,881 users.

Directed network. Keeps who rated whom. A user's in-degree \(k^{in}\) is the number of positive ratings received.
Undirected network. Two users are linked if either rated the other. Path lengths count links; a higher score is not a longer distance.

03 · Structure

A sparse small world with hubs

Eight measures from the course describe the shape of the network.

Links per user, \(\langle k\rangle = 2L/N\). The largest hub has 788.

0.11%Density

0.155Clustering

Chance that two neighbours of a user are also linked, averaged over users.

Users who can reach each other. The network is not connected, so distances use this part.

3.76Mean distance

Average number of links on a shortest path between two users.

14Diameter

The longest of all shortest paths.

0.504Modularity

How much more often links stay inside communities than random wiring would allow.

−0.145Assortativity

Correlation of degrees at the two ends of a link. Negative: hubs link to small users.

Paths are shorter than in a random network of the same size while clustering is about 150 times higher: the signature of a small world. All five largest communities are weak communities in Barabási's sense, with more of their members' link ends inside the group than outside, but which users land in which group changes when the community algorithm is rerun.

04 · Theory

What the models get right, and wrong

We compared the network with three references: an Erdős–Rényi random network with the same users and links, a Barabási–Albert network grown by preferential attachment, and a degree-preserving randomization that keeps every user's degree but shuffles who is linked to whom.

Keeping the degrees reproduces the short paths, but not the clustering or the communities: those come from how users chose their partners.

Heavy-tailed, but not strictly scale-free

A scale-free network has a degree distribution \(P(k) \propto k^{-\gamma}\). Fitted properly, by maximum likelihood rather than a straight line on a log–log plot, the tail gives \(\gamma = 2.09\): heavier than the \(\gamma = 3\) of the BA model. Yet a lognormal tail fits better; above about 100 links the data bend down.

BA's growth rule also fails: 70.5% of links join two users who were already present. Barabási's internal-link model allows exactly that, and for the measured \(m = 0.99\) and \(n = 2.35\) it predicts

\(\gamma = 2 + \dfrac{m}{m + 2n} = 2.17\)

inside the fitted range.

Hubs link to small users

Degree correlations ask whether hubs connect to other hubs. Here they do not: the assortativity is \(r = -0.145\).

Much of this is forced. In a simple network a hub cannot find enough other hubs, and above the structural cutoff \(k_s = \sqrt{\langle k\rangle N} \approx 193\) that pushes \(r\) below zero. Our largest hub has 788 links, and randomizations that keep every degree already give \(r = -0.114\).

The extra pull is small but real: users with a single link are attached to neighbours with 181 links on average, against 93 after randomizing.

05 · The focused question

How reputation concentrated over time

Every rating has a timestamp, so we can follow the network as it grew and ask who received each new rating.

Accumulated ratings concentrate

Counting all ratings received so far, the top 1% of users held 15.5% of positive ratings at the end of 2011 and 23.5% by 2015. The rise also holds within the same group of users present in 2011, so it is not just new users joining.

The share of each year's new ratings seems to fall after 2013, but ratings collapsed from 11,138 to 929 a year. Redrawn to the same 743 ratings every year, 2013 and 2015 overlap: most of that fall is a volume effect.

Who receives the next rating?

This is how the course measures preferential attachment: for every new rating, compare the user who received it with everyone who could have. Users with 32 or more earlier ratings were chosen 12.7 times as often as chance, and the fitted rule \(\Pi(k) \propto k^{\alpha}\) has \(\alpha = 1.07\), almost exactly BA's linear attachment.

But that compares a dormant newcomer with an active trader. Against users with the same tenure and recent activity, the ratio falls to 1.65 and \(\alpha\) to 0.68. Recent activity, not reputation, explains most of the advantage, and about half of all ratings simply return an earlier one, usually within minutes.

06 · Robustness

Robust to random failures, fragile to attacks

Percolation theory predicts when a network falls apart. A giant component exists while \(\kappa = \langle k^2\rangle / \langle k\rangle > 2\), the Molloy–Reed criterion, and removing a random fraction \(f\) of users destroys it at the critical threshold

\(f_c = 1 - \dfrac{1}{\kappa - 1} = 0.986\)   for   \(\kappa = 71.9\)

Random removal barely matters: the giant component survives until about 93% of users are gone. Removing the most-connected users first breaks it after only 15%. Randomized networks with the same degrees break at the same point, so the hubs are the weak spot.

07 · What it means

What this means for a web of trust

01

Reputation stays concentrated

By 2015, 56 accounts held 23.5% of positive ratings. Ratings never expire here, so a high score may describe the past more than the present.

02

A few accounts hold it together

Losing or compromising a handful of hubs would disconnect far more of the trust record than the same number of random departures.

03

Counts overstate independent opinions

About half of the ratings return an earlier one, often within minutes, so a rating count is not a count of independent endorsements.

04

Activity beats reputation

Recent activity explains most of the pull of highly rated users. We cannot separate it from trading volume, which the data do not record.

Limits: ratings are opinions, not verified trades; the data have no registration dates or trade volumes; one person may hold several IDs; the users in the animation were chosen using all years.

08 · Reproduce

Every number can be rebuilt

The repository has the analysis scripts, explanatory notebooks, stored results and a checker that compares a new run with the recorded one. With Python 3.12:

# set up the environment
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
# put soc-sign-bitcoinotc.csv.gz from SNAP in data/, then
.venv/bin/python scripts/reproduce.py                        # eight analyses, 15–30 minutes
.venv/bin/python scripts/verify_reproduction.py --check-manifest
